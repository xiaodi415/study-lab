\# lock / Monitor / Interlocked



\## 实测（8 线程 × 50 万次）

| 版本 | 耗时 | 结果 | 丢失 |

|---|---|---|---|

| 无锁 | 5.1 ms | 1509493 | 2490507 |

| lock | 321.7 ms | 4000000 | 0 |

| Interlocked | 66.3 ms | 4000000 | 0 |

| Monitor 手动 | 455 ms | 4000000 | 0 |



\## 三个结论

1\. counter++ 是读-改-写三步，非原子，多线程会丢更新

2\. lock = Monitor.Enter/Exit + try/finally，慢但通用

3\. Interlocked = CPU 原子指令，只适合单变量，快 5 倍



\## 锁对象三条铁律

私有、引用类型、readonly

禁止：string（驻留）、this（外部可锁）、typeof（全局）、值类型（编译错）



\## 竞态的其他场景

检查-然后-使用、懒加载单例、遍历时修改集合、标志位可见性



\## 选型

单变量 → Interlocked

多变量/复杂逻辑 → lock

跨进程 → Mutex

读多写少 → ReaderWriterLockSlim



\## 面试一句话

counter++ 非原子会丢更新；lock 是 Monitor + try/finally，慢但能保护多步；

Interlocked 是原子指令，只适合单变量且快 5 倍；锁对象必须私有/引用/readonly。
