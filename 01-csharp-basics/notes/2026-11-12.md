\# GC 与 IDisposable



\## 三个结论

1\. GC 只回收托管内存；文件句柄、串口、Socket 等外部资源必须手动释放

2\. using 就是 try/finally 的语法糖，编译后等价于 try{...}finally{ if(x!=null) x.Dispose(); }

3\. 异常路径、return 路径都会执行 finally，所以 using 里抛异常或提前 return 都不会漏关



\## 两种写法

\- using (...) { }        → 出了大括号就释放

\- using var x = new X(); → 释放点是所在大括号结尾，不是声明那一行



\## 幂等

Dispose 里加 if (\_disposed) return;，重复调用不会出错。



\## finally 救不了的三种情况

Environment.Exit()、进程被强杀/断电、StackOverflowException。

所以「程序关了但端口仍被占用」的根因通常是这三种，不是 using 写错。



\## 终结器

\~类名() 是最后兜底，但时机不确定、回收要两轮 GC。

业务代码不靠它，靠 using 或 SafeHandle。



\## 工作关联

SerialPort / TcpClient 都实现 IDisposable。

不 using 会导致 COM 口被占用，下次打开报「拒绝访问」，产线常见故障。



\## 面试一句话

GC 只管托管内存；非托管资源必须用 using 或 try/finally 显式释放。

using 编译后就是 try/finally，异常和提前 return 路径同样会释放。
