# string 不可变与 StringBuilder 性能实测

> 环境：.NET 9.0.18 · Release · 3 轮取最小值 · 循环内 `s += "x"` vs `sb.Append('x')`

## 一、实测数据

| 规模 n | `+=` 拼接 | `StringBuilder` | 倍数 | `+=` 分配内存 |
|---|---|---|---|---|
| 1,000 | 0.41 ms | 0.01 ms | 32.0x | 1.0 MB |
| 4,000 | 1.85 ms | 0.02 ms | 79.8x | 15.4 MB |
| 16,000 | 25.88 ms | 0.04 ms | 714.9x | 244.5 MB |

## 二、分配量精确符合 O(n²)

`+=` 每次都要新建字符串并复制全部已有内容，第 i 次复制 i 个字符，总复制量：

```
1 + 2 + ... + n = n(n+1)/2 ≈ n² / 2 个字符
```

| n | 理论字符数 | 理论字节（UTF-16，每字符 2 字节） | 实测 |
|---|---|---|---|
| 1,000 | 50.0 万 | 1.00 MB | 1.0 MB |
| 4,000 | 800 万 | 15.26 MB | 15.4 MB |
| 16,000 | 1.28 亿 | 244.1 MB | 244.5 MB |

三个规模全部吻合，**实测分配量与 n²/2 完全对上**，这是 O(n²) 最硬的证据。

## 三、耗时增长验证复杂度

| 区间 | 规模倍数 | 实测耗时倍数 | O(n²) 理论 |
|---|---|---|---|
| 1,000 → 4,000 | 4x | 4.5x | 16x |
| 4,000 → 16,000 | 4x | 14.0x | 16x |
| 1,000 → 16,000 | 16x | 63.1x | 256x |

观察：

- 1,000 → 4,000 只有 4.5x，远低于理论 16x。原因是**小规模时固定开销（方法调用、对象头、分配器）占比高**，复制本身还不是瓶颈
- 4,000 → 16,000 是 14.0x，已经很接近 16x —— 规模越大越接近理论值
- 折算吞吐量：1,000 时约 2.4 GB/s，4,000 时约 8.6 GB/s，16,000 时约 9.9 GB/s，说明小规模被固定成本稀释

**结论：判断复杂度要看增长趋势，不能看单点倍数。**

StringBuilder 则是线性的：0.01 → 0.02 → 0.04 ms，规模 16 倍、耗时约 4 倍。

## 五、原理

`string` 是不可变类型，`s += "x"` 等价于：

```csharp
s = string.Concat(s, "x");   // 新建对象 + 复制全部内容 + 追加
```

- 每次循环都分配一个新字符串，旧的立刻变成垃圾
- 时间 O(n²)，空间上产生 n 个临时对象，全部要 GC 回收

`StringBuilder` 内部是可变 `char[]`：

```csharp
sb.Append('x');   // buffer[len++] = 'x'   → O(1)
```

只有容量不足时才扩容，全程 O(n)，最后 `ToString()` 复制一次。

## 六、为什么 string 要设计成不可变

1. **线程安全**：不可变对象可自由共享，无需加锁
2. **字符串驻留**：相同字面量只存一份，`"a" == "a"` 常指向同一对象
3. **哈希可缓存**：`string` 常做 `Dictionary` 的键，哈希值只需算一次
4. **安全性**：作为参数传递时，不会被调用方篡改内容

代价就是每次修改都要复制 —— 所以需要 `StringBuilder` 补位。

## 七、怎么选

| 场景 | 选择 |
|---|---|
| 循环内累积（次数多 / 未知） | `StringBuilder` |
| 少量固定拼接 `a + b + c` | 直接用 `+`，编译成一次 `String.Concat` |
| 循环内累积字符串插值 `$"{x}"` | `StringBuilder`（插值同样会分配） |

## 八、测量方法上的两个坑

1. **小规模时倍数失真**：1,000 → 4,000 只有 4.5x，固定开销占比大，不能拿来证明复杂度
2. **`StringBuilder` 的 0.01 ms 已接近 `Stopwatch` 精度下限**，分母不准，所以「714 倍」应该表述为「**几百倍**」

## 九、面试一句话

> string 不可变，每次修改都要复制整个内容，循环拼接是 O(n²)；StringBuilder 用可变缓冲区把追加降到 O(1)，代价是最后一次 ToString 的复制。
>
> 实测 1.6 万次拼接：`+=` 分配 244 MB、耗时 26 ms，StringBuilder 只需 0.04 ms。
> 判断复杂度要看增长趋势，不能只看单点倍数。
